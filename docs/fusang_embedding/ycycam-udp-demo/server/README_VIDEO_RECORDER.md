# 🎥 视频循环录制功能说明

## 功能概述

本系统实现了通过UDP接收ESP32-CAM拍摄的视频流，并在Linux服务器上实现**循环存储最近1小时**的视频功能。

## 核心特性

### 🔄 循环存储机制
- **最大存储时长**: 1小时（3600秒）
- **分段时长**: 每1分钟生成一个独立的MP4文件
- **自动清理**: 超过1小时的视频文件会被自动删除
- **存储目录**: `ycycam-udp/server/recordings/`

### 📹 视频编码
- **编码格式**: MP4V (MPEG-4)，兼容性好
- **分辨率**: 640x480 (与摄像头一致)
- **帧率**: 15 FPS (均衡质量与存储空间)
- **时间戳**: 每帧都叠加录制时间水印

### 📊 管理界面
- **实时状态**: 录制状态、FPS、分段数量、存储空间
- **视频列表**: 按时间倒序显示所有录像
- **在线播放**: 直接在浏览器中播放历史视频
- **下载功能**: 支持下载任意视频分段

## API接口

### 1. 获取录制状态
```
GET /recorder_status
```
返回示例：
```json
{
  "recording": true,
  "current_segment": "video_20260515_031949.mp4",
  "segments_stored": 1,
  "total_storage_size_mb": 2.5,
  "recording_fps": 14.8
}
```

### 2. 获取视频列表
```
GET /video_list
```
返回所有已录制的视频文件信息。

### 3. 播放/下载视频
```
GET /video/<filename>
```
直接提供MP4文件，支持流式播放和下载。

### 4. 录像管理页面
```
GET /recordings
```
完整的Web管理界面。

## 技术实现

### 视频录制流程
1. UDP线程接收到完整的JPEG帧
2. 将帧数据传递给录制模块
3. 录制模块解码JPEG → OpenCV Mat
4. 添加时间戳水印
5. 写入MP4视频文件

### 循环清理机制
- 每次创建新分段时触发清理
- 按文件名中的时间戳判断是否过期
- 过期文件立即删除，确保不超过存储限制

### 线程安全设计
- 使用deque作为帧缓冲区
- 锁机制保护缓冲区访问
- 独立的录制线程，不影响视频流实时性

## 自定义配置

如需调整参数，修改 `web_receiver.py` 中的 `init_recorder()` 函数：

```python
recorder = get_recorder(
    video_dir="recordings",           # 存储目录
    segment_duration=60,             # 分段时长(秒)，默认1分钟
    max_storage_duration=3600,        # 最大存储(秒)，默认1小时
    fps=15,                           # 录制帧率
    resolution=(640, 480)             # 分辨率
)
```

## 常见问题

**Q: 为什么第一个视频要等1分钟才出现？**
A: 系统每1分钟生成一个完整的分段文件。正在录制的文件也在目录中，但可能不完整。

**Q: 如何保留更长时间的录像？**
A: 修改 `max_storage_duration` 参数，例如改为 `7200` 即保留2小时。

**Q: 可以调整分段时长吗？**
A: 可以，修改 `segment_duration` 参数。建议1-10分钟之间。

**Q: 录制的视频没有声音？**
A: 当前版本只录制视频，不支持音频。ESP32-CAM的音频传输需要额外开发。
