# ycycam-udp 项目更新日志

## 2026-05-09 - 核心功能重大升级

### 🚀 AI检测升级
- **模型升级**: 从 YOLOv8n (6.2MB) 升级为 **YOLOv8m (49.7MB)**，检测精度大幅提升
- **检测开关**: 新增物体检测开关按钮，可随时开启/关闭
  - 按钮位置: Web界面控制栏最右侧
  - 开启状态: 绿色背景，显示 "🔍 检测开"
  - 关闭状态: 灰色背景，显示 "🔍 检测关"
  - 关闭时自动隐藏所有检测框，显著降低CPU占用
  - API接口: `/detection_on`、`/detection_off`
- **检测配置优化**:
  - 置信度阈值: 0.4 → **0.6**（减少误报）
  - IoU阈值: 0.45 → **0.3**（减少重复检测）
  - 检测间隔: 10 FPS → **每6帧检测一次**（平衡性能与实时性）
  - 结果缓存: 新增1秒缓冲，减少检测框抖动

### 🎨 显示体验优化
- **检测框文字正立显示**: ✅ **重大改进**
  - 移除了对 `detectionOverlay` 的整体 CSS 变换
  - 检测框和标签文字不再跟随视频翻转/旋转
  - 后端检测时应用与前端一致的图像变换
  - 返回的检测坐标已是变换后的正确位置
  - 用户体验大幅提升，无论视频如何翻转旋转，检测文字始终清晰可读

- **视频流自动显示**: ✅ **修复完成**
  - 修复了打开页面时需要手动刷新才能显示视频流的问题
  - 增加 `DOMContentLoaded` 事件监听
  - 增加 `window.load` 事件监听
  - 页面加载完成后自动调用 `updateUI()` 初始化显示
  - 使用 `Date.now()` 替代 `Math.random()` 确保URL唯一性
  - 增加强制浏览器重渲染机制（opacity动画）

### 📸 截图功能增强
- 截图时自动应用当前的翻转/旋转变换
- 自动添加时间戳水印（格式: YYYY-MM-DD HH:MM:SS）
- 文件名包含时间戳，避免覆盖
- 下载后提示"照片已保存"状态信息

| 🚗 汽车 | car | 机动车 |
| 🍼 瓶子 | bottle | 各种瓶子 |

| 🪑 椅子 | chair | 座椅、椅子 |
| 🐕 狗 | dog | 犬类动物 |
| 🐱 猫 | cat | 猫科动物 |

### 人脸检测
- 算法: OpenCV Haar Cascade Classifier
- 模型: `haarcascade_frontalface_default.xml`
- 参数: scale=1.2, minNeighbors=5, minSize=(50,50)

## 🔌 API 接口列表

### 检测控制
| 接口 | 方法 | 说明 |
|------|------|------|
| `/detections` | GET | 获取最新检测结果（包含 enabled 状态） |
| `/detection_on` | GET | 开启物体检测 |
| `/detection_off` | GET | 关闭物体检测 |

### 视频控制
| 接口 | 方法 | 说明 |
|------|------|------|
| `/set_transform` | GET | 设置视频翻转/旋转状态 |
| `/start` | GET | 开始视频流 |
| `/stop` | GET | 停止视频流 |

### 状态查询
| 接口 | 方法 | 说明 |
|------|------|------|
| `/status` | GET | 获取系统状态（FPS、帧数、带宽等） |
| `/stream` | GET | MJPEG 视频流 |

### `/detections` 响应格式
```json
{

  "enabled": true,
  "objects": [
    {
      "label": "person",
      "confidence": 0.892,
      "box": [100.5, 50.2, 80.3, 120.7]
    }
  ],
  "faces": [
    {
      "label": "face",
      "confidence": 0.95,
      "box": [200.0, 100.0, 60.0, 60.0]
    }
  ]
}
```

## 🏗️ 架构改进

### 后端改进
1. **全局状态变量**
   - 新增 `_detection_enabled` 变量控制检测开关
   - 检测线程循环中检查该变量，关闭时跳过敏感计算
   - 与视频变换状态（`_flip_h`、`_flip_v`、`_rotate`）协同工作

2. **多线程优化**
   - UDP接收线程: 专注网络IO
   - 检测线程: 独立运行，可随时暂停
   - HTTP线程: 处理Web请求和MJPEG流
   - 线程间通过共享变量通信，使用锁保证安全

3. **视频变换同步**
   - 前端设置的翻转/旋转状态同步到后端
   - 后端检测前先对图像应用相同变换
   - 确保检测坐标与显示坐标一致

### 前端改进
1. **初始化优化**
   - DOM就绪后立即初始化
   - 页面完全加载后再次确认显示
   - 避免因资源加载顺序导致的显示问题

2. **检测框渲染**
   - 移除 overlay 整体变换
   - 检测框直接使用后端返回的变换后坐标
   - 文字始终保持正立，无需反向变换

## 📊 性能指标

### 系统资源占用
- **内存**: ~500MB（模型加载后）
- **CPU**: 30-80%（取决于检测开关状态）
  - 检测开启: 50-80%
  - 检测关闭: 10-20%
- **网络**: 2-8 Mbps（取决于视频分辨率）

### 典型性能参数
| 参数 | 数值 |
|------|------|
| 视频分辨率 | 640x480 |
| 接收帧率 | 30-40 FPS |
| 检测帧率 | ~5 FPS（每6帧检测1次） |
| 端到端延迟 | ~200ms |
| UDP端口 | 5000 |
| HTTP端口 | 8000 |

## 🎯 已知限制

1. **检测类别固定**: 当前只支持12种预设物体，如需扩展需要重新训练模型
2. **旋转90°限制**: 检测框坐标在旋转90°时需要额外计算，目前只支持水平/垂直翻转后的正确显示
3. **单客户端限制**: Web界面同时只推荐一个客户端访问，多客户端会增加CPU负载
4. **模型下载**: 首次运行需要自动下载YOLO模型，需要网络连接
